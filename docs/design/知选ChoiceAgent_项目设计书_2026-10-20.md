项目设计书 v1.0 · 2026-10-20


---

## 知选 ChoiceAgent

个性化商品搜索、推荐与决策助手 · 项目设计书 v1.0

为搜广推算法与 Agent 应用开发两类实习共同设计。以同一套商品召回、排序和证据服务，连接普通搜索页面与多轮决策助手。

适用画像：东北大学计算机本硕，学硕 0812，2028 年 6 月毕业，首份实习；2026 年 11 月开始投递。

研究基础：SAILRec 已获 EMNLP 2026 主会接收（第一作者）；PACERec 为共同第一作者研究草稿，拟投 WWW 2027，尚未完成正式全文提交。

资源：A6000 服务器单卡 + Windows RTX 3060 笔记本；本地开源模型可独立运行，DeepSeek API 可选。

交付节奏：两周形成可演示版本，六周形成可复现、可评测、可写入简历的完整作品。

设计与公开资料核验日期：2026-10-20。本文件提供拟实施方案；所有规模、耗时、预算和验收数值均为规划或目标，未实际训练、部署或测得项目效果。

## 01 / 项目决策与阅读导航

一个能解释“为什么这样推荐”，也能完成“下一步操作”的系统。

### 建议采用的项目定义

知选面向家庭办公商品选型：用户描述用途、预算和偏好，系统检索商品、给出个性化候选、引用属性比较，并通过对话修正条件或保存候选清单。底层的搜索、推荐、排序服务独立于大模型；Agent 决定何时澄清、调用哪项工具、是否继续查询。

| 选择 | 本设计的取舍 |
| --- | --- |
| 业务主线 | 商品发现 → 约束筛选 → 个性化排序 → 证据比较 → 偏好反馈。 |
| 算法主线 | BM25 + 文本向量 + 协同过滤，分别评估召回、排序、长尾和冷用户。 |
| Agent 主线 | 结构化工具、有限轮次决策、会话状态、显式记忆、证据校验和失败恢复。 |
| 实现方式 | Python 模块化单体；FastAPI + SQLite FTS5 + FAISS + Streamlit。 |
| 模型方式 | 本地 Qwen 为完整运行路径；DeepSeek 为可替换提供方，按预算手动启用。 |
| 成果要求 | 能复现的工程、三类评测、真实测量、成功与失败轨迹、短演示视频。 |

### 如何阅读

第 02—04 节说明场景、个人优势和范围；05—11 节为数据与算法；12—18 节为 Agent、资源和工程；19—22 节定义评测；23—26 节给出执行计划、作品交付与扩展；27—28 节列参考资料及配置约定。

搜广推在此以搜索、推荐为主。广告相关的候选排序、特征与实验思路可迁移；广告投放、竞价与收益优化只做后续独立模拟扩展。

## 02 / 用户场景与产品边界

用三段具体交互展示算法和 Agent 的共同价值。

| 场景 | 用户动作 | 系统必须表现 |
| --- | --- | --- |
| 找商品 | “想整理小书桌，找桌面收纳架，预算 40 美元以内。” | 解析用途与预算；词面/语义召回；只返回价格已知且满足预算的候选，附属性证据。 |
| 改偏好 | “不要木质，优先我刚刚喜欢的简洁风格。” | 新约束优先；喜欢是软偏好；重新检索/排序，说明变化来自何处。 |
| 比较与保存 | “比较前两个的尺寸；把更合适的加入候选清单。” | 比较已返回的合法 ID；缺失尺寸显示未知；确认指代明确后幂等保存。 |

以上对话仅为功能示例，不声称数据集中一定有对应商品。演示前从冻结目录选取真实有据可查的案例；另保留无匹配和缺失属性的失败案例。价格统一显示“数据集采集时的美元价格”，不冒充当前人民币售价。

### 界面只需要三个区域

左侧：输入、预算与类别过滤、临时偏好；中间：搜索结果卡片和对话；右侧：可展开的比较表、引用证据、执行轨迹。普通用户默认只看结果和原因，调试详情由演示者主动展开。

### 明确完成与未完成的动作

候选清单是本地收藏，不是购物车下单。MVP 不接支付、物流、库存、实时比价或浏览器自动购买。用户未提供关键条件时，允许一次澄清；有多个合理答案时给候选与取舍，不强行编造唯一最佳商品。

“同时服务两类岗位”的核心是同一请求可从算法指标追溯到工具轨迹，再追溯到最终结果；不是把一个聊天窗口附着在独立的推荐实验上。

## 03 / 论文优势如何转成工程能力

依据两份附件理解技术内容；作者与接收状态采用用户提供的信息。[P1][P2]

| 现有研究 | 可迁移到本项目 | 本次补上的证据 |
| --- | --- | --- |
| SAILRec：CF → LLM | 协同信息需要有效对齐与利用。构造来源明确的偏好上下文，比较有/无协同信号时的候选与解释。 | 工具只返回可解释的行为依据；验证是否因历史偏好而偏离当前查询。 |
| PACERec：LLM → 推荐 | 文本语义可适配行为空间，物品表示可离线缓存。优先实现语义、CF 与融合基线。 | 可选小型语义→CF 映射；报告长尾分桶、推理成本和相同容量基线。 |
| 两篇论文共同基础 | 表示学习、推荐评测、消融、冷启动与长尾问题意识。 | 数据管道、接口契约、服务部署、故障处理、可复现实验与成本管理。 |

### 只做一个受控的算法亮点

先完成“协同候选 + 语义候选 + 查询相关性约束”的可解释融合。若第 4 周后仍有余力，再做小型共享适配器，验证语义是否更贴近行为。完整复现 SAILRec 的 7B 偏好打分与 PACERec 的流式适配都不列为主线前置条件。

### 两种面试讲法，共用同一个项目

搜广推讲法：数据如何划分，召回上限在哪里，CF 与语义何时互补，相关性与个性化如何冲突，收益是否来自公平比较。Agent 讲法：如何选择工具、验证参数、维护状态、引用证据、处理超时和预算，任务成功如何客观判断。

不要将论文离线 AUC、NDCG 写成线上 CTR、GMV；不要将未提交稿件写成“WWW 在审”。项目的创新点是可测量的系统闭环，研究亮点是可选的加分项。

## 04 / 范围分层与完成标准

按每周 20—25 小时设计；时间不足时先删扩展，不删评测和可运行性。

| 阶段 | 必须交付 | 完成门槛 |
| --- | --- | --- |
| 第 2 周 / MVP | 2,000—5,000 商品的小目录；BM25/语义检索；ItemCF 或内容历史聚合；普通搜索页；search、compare 两工具 Agent。 | 20 个开发场景可回放；合法商品 ID；预算过滤正确；有引用、超时退回卡片；可录 3 分钟视频。 |
| 第 6 周 / 完整版 | 按数据审计扩展到目标 1万—3万商品；融合与冷启动；偏好/收藏；日志；推荐、搜索、Agent 三套正式评测。 | 锁定数据与版本；复现脚本；质量—延迟—成本表；可展示成功与失败；简历只填实测值。 |
| 稳定后 / 三选一 | 小型语义→CF 适配器；模拟广告位；更大目录的 ANN 实验。 | 一次只选一项，以核心评测通过为前提；新增收益可归因、成本可解释。 |

### 六周内不作为必做项

不训练基础大模型，不做强化学习 Agent，不堆多个自治 Agent，不引入分布式数据平台或 Kubernetes。复杂序列模型、LoRA、线上 A/B 与真正广告点击建模均可后续补充。现有论文已能证明研究能力，这个项目应优先证明工程闭环。

### 两周版本也要同时体现两个方向

推荐侧先展示已有历史的样例用户与新用户的内容回退；Agent 侧先有搜索与比较的自主工具选择。长期记忆、复杂融合、正式统计实验可以后移，但两周演示不能只有静态页面，也不能只有聊天回复。

目录、用户和交互数量是预算，不是预先承诺的实测规模。第 1 周按真实稀疏度调整；小目录上的扎实评测优于不可复现的大规模口号。

## 05 / 总体架构

离线产物版本化；在线共享排名服务；模型提供方可替换。

**流程图文字版：** 原始商品/评论 → 清洗与时间切分 → SQLite/FTS5、FAISS、CF 模型；普通搜索与 Agent 共用 FastAPI 排名服务；Agent 通过工具访问排名、比较与偏好，调用本地 Qwen 或可选 DeepSeek；结果带证据，反馈进入独立日志。

### 关键边界

ranking 模块不依赖 LLM；Agent 不能绕过约束过滤直接生成商品。离线训练不在接口启动时执行。商品、索引、CF、提示词与评测集都带版本，启动时检查 ID 集合和维度是否一致。

一个 FastAPI 服务承载业务；模型推理可以独立进程。SQLite 负责目录与轻量状态，FAISS 负责向量检索。初期只支持本地演示与低并发，性能结论明确注明机器和配置。

图中反馈先更新会话偏好；批量再训练是可选离线作业，不承诺点击一次就在线更新模型参数。

## 06 / 数据来源与抽样方案

主数据选择 Amazon Reviews 2023 的 Office_Products；先审计再固定子集。[S1]

该类目包含商品元信息和评论。选择家庭办公场景便于表达预算、材质、尺寸和用途，同时保留较宽目录支持协同信号。可从桌面整理等子类开始演示；历史推荐实验不必被演示的小子类限制。

| 步骤 | 具体处理与输出 |
| --- | --- |
| 下载与流式检查 | 优先官方原始 JSON 文件。记录 URL、日期、校验和、字段及缺失率；先抽少量行确认格式，随后流式扫描，不全量塞入内存。 |
| 身份与时间规范 | 以 parent_asin 对接元信息并合并变体。时间字段按文档和实际数量级校验单位，显式转 UTC；无效时间隔离，不静默猜测。 |
| 先确定时间边界 | 对约定类目清洗后的事件，以全局时间约 80%/90% 分位点设 T0/T1，同一时间戳不拆分；固定具体 UTC 边界。 |
| 仅用训练记录选目录 | 由 T0 前训练交互确定商品 ID，再关联静态元信息；按训练频次分层和固定种子抽至 1万—3万。目录文本可见是假设，不按测试命中率选商品。 |
| 控制计算量 | 训练交互目标上限 50万；超出时按训练用户确定性抽样并保留历史。抽样后重算频次；I_train 仅含最终仍有正反馈的商品，零交互另列冷物品。 |
| 目录偏稀疏时 | 先扩大到完整 Office_Products；若仍不满足活跃用户要求，降低目录/用户目标，报告覆盖率；不借未来评论凑训练活跃度。 |

两周 MVP 单独冻结元数据小目录，用显式喜欢做内容个性化，不等待完整评论扫描；历史推荐管道在第 3 周完成，复用 schema 和服务。完整评测注明自定义子集。评论不是曝光、点击或购买路径日志。

原始数据与图片不随项目仓库打包；发布处理脚本、获取说明与自制小样例。代码仓库的许可证不自动等于原始数据的再分发许可。

## 07 / 数据表、证据与版本

所有工具结果最终能够追溯到商品字段或显式用户事件。

| 实体 | 最小字段与约束 |
| --- | --- |
| catalog_item | item_id(parent_asin), title, category_path, brand?, price_usd?, attributes, catalog_version。价格缺失为 null，单位固定 USD。 |
| interaction | user_id_hash, item_id, rating, review_time_utc, source, split。保留原始评分；正反馈定义为 rating≥4，不把所有评论当喜欢。 |
| evidence | evidence_id, item_id, field_path, value, source_locator, snapshot_version。商品事实取元信息；评论观点与事实分开。 |
| preference | preference_id, user_id, key, value, scope, provenance, source_event_id, updated_at, expires_at?。可查看、删除。 |
| feedback / shortlist | event_id, user/session_id, request_id, item_id, action, origin, time。event_id 去重；清单只操作合法且可见商品。 |
| trace / manifest | trace_id、数据/索引/模型/prompt/schema 版本、候选来源、工具结果摘要、用量、耗时、错误类别、随机种子。 |

### 缺失值和派生字段

price_usd 未知时不能通过严格预算过滤；“轻便”“安静”等没有可核对属性时仅是软意图，不能伪装成硬保证。字段抽取优先结构化元信息与明确规则；若用 LLM 抽取，必须保存原文片段与验证状态。

average_rating、rating_number、bought_together 等全量汇总字段从历史预测特征中剔除；热门度、评分聚合只从训练分区重算。用户历史摘要同样在切分后生成。

元信息中的价格为采集时美元价格，标题和描述也不是逐时历史快照。[S1] 文本增强实验须注明“静态目录内容假设”，不能声称还原了真实历史线上系统。

## 08 / 时间切分与推荐任务定义

先冻结训练世界，再验证未来目标；搜索与 Agent 使用另一个冻结场景集。

**流程图文字版：** 全局事件时间：训练≤T0；验证(T0,T1]；测试>T1。目录、用户画像、热门度、CF 与归一化仅用训练数据；模型和画像不滚动更新。每个用户在验证/测试窗口的首个合格正反馈为目标。

| 规则 | 实施约定 |
| --- | --- |
| 重复评论 | 按用户—父商品保留最早有效记录；其余进入审计计数。评分阈值、去重和时间规则在看模型结果前锁定。 |
| 主评测用户 | 训练期至少 3 个正反馈；目标商品在训练目录；各窗口取首个未在训练中交互的正反馈目标。 |
| 候选集 | 统一使用冻结目录 I_train，屏蔽用户训练期已交互商品；各模型一致。全目录分块计算排名，不以 99 个抽样负例为主结果。 |
| 未覆盖群体 | 单列新用户、未入训练目录目标、缺元信息、历史不足、重复消费等剔除数量；主结果只代表所报告人群。 |
| 验证与测试 | 验证选超参和 checkpoint；测试只在锁定后正式运行。主协议不合并验证重训，避免版本与历史口径混乱。 |

历史推荐衡量“固定历史预测未来评论相关商品”。演示与 Agent 任务衡量“冻结商品快照中的需求完成”，二者共享服务实现，但不合并成一个含义不清的总指标。

长尾：按训练目录商品交互频次排序，后 80% 为 tail，平频以 ID 固定排序。长尾不是零交互新物品；若做新物品实验必须单独定义。

## 09 / 召回：词面、语义与行为三路

候选来源可观察；每一路都有独立基线和降级方式。

| 路线 | 算法与初始配置 | 适用与限制 |
| --- | --- | --- |
| 词面召回 | SQLite FTS5 BM25，title/category/features 分字段；每路初始 top200。 | 擅长型号、品牌和精确词；FTS5 的 BM25 分数越低越好，排序方向要单测。[S2] |
| 语义召回 | Qwen3-Embedding-0.6B；统一文本模板、截断与指令；1024维，L2 归一化；FAISS IndexFlatIP。 | 查询与文档使用同一编码约定。精确余弦检索作为基准；向量离线计算，查询在线编码。[S3][S4] |
| 协同召回 | 训练期 ItemCF 为必做；BPR-MF 为可选替代，不必两个都深入。对历史喜欢项聚合邻居。 | 已有用户或会话喜欢项可用；全新用户不能随机分配 MF 向量冒充个性化。 |
| 冷用户回退 | 兴趣类目 + 训练热门 + 显式喜欢商品的语义相似。 | 页面标记非个性化/初始偏好来源；让用户可选择 2—3 个感兴趣商品。 |

### 中英文检索处理

数据以英文为主，交互允许中文。MVP 默认跨语言 Dense + 小词表英文扩展；若使用模型改写，则在规划阶段完成并计入统一 LLM/费用/时间预算，不能藏在 search 工具中。保留原文与改写，品牌、型号、数值、否定不能丢失。

约束可预过滤时先过滤，否则候选合并后过滤。初始最多 600 个去重前候选，不足时每路最多扩大一次至 400（总上限 1,200）；最终取 10 个，展示 3—5 个。结构化无解须经 SQL 全目录核验；未穷尽的空召回返回 RETRIEVAL_INCOMPLETE，不能宣称无解。

30,000 × 1024 × 4 字节约 123 MB，仅为 float32 向量，不含模型/索引/元数据。此规模先用 CPU 精确检索；引入 HNSW 前必须测到收益并报告相对精确检索的召回损失。[S3]

## 10 / 排序：相关性先于个性化

先可用、再相关、再偏好；不用不可比原始分数直接相加。

### 第一阶段：词面与语义合并

```text
RRF(q, i) = Σ[r ∈ {lexical, dense}] w_r / (k0 + rank_r(i))
初值：k0 = 60，w_lexical = w_dense = 1；缺席路线贡献 0。
候选 = lexical ∪ dense ∪ collaborative；保留每路 rank 与原始分数。
```

RRF 为初始秩融合方案。CF 独有候选仍需计算查询相关性，并通过类别/用途门槛；与当前查询无关的历史偏好商品不能靠协同高分挤入结果。

### 第二阶段：约束与查询相关性

硬过滤由程序执行：已知预算、显式排除品牌、可验证类别或属性。基础相关性使用 RRF 与余弦/类目规则；完整版本可对 top30 使用 Qwen3-Reranker-0.6B。阈值在开发集定，若证据不足则返回少量候选或澄清。[S5]

### 第三阶段：受限的偏好加权与去重

```text
仅对通过硬约束和相关性门槛的候选：
score = (1 - λ) × query_score_01 + λ × preference_score_01
λ ∈ {0, 0.1, 0.2}，只在开发集选择。
无历史时 λ=0；无查询的推荐请求使用单独的推荐评分。
```

query_score_01 可用候选内分位秩，preference_score_01 用 CF/喜欢项相似的分位秩；缺失为中性值并记录。分位是排序特征，不是点击概率。统一固定并列 ID 顺序。去重以父商品为主，可加轻量类目/品牌多样性约束并报告排序影响。

必须比较 λ=0；个性化不能保证每条请求都提升。精确型号查询可直接关闭偏好加权。重排器只处理小候选集，不让生成模型逐个阅读全目录。

## 11 / 协同建模与可选研究亮点

优先一个可信的行为基线；再决定是否引入学习型适配。

### 必做：可解释 ItemCF

以训练正反馈构建稀疏用户—商品矩阵，计算归一化共现相似度；只保留每个商品 top100 邻居，避免构造全量稠密相似矩阵。用户得分由历史喜欢项邻居加权和得到；解释可回溯到贡献最大的历史项。热门度与内容历史聚合是必要对照。

### 可选：BPR-MF

若希望增加可训练排序经验，可用 64/128 维 MF，BPR 采样未观察商品作为对比项。未观察不等于讨厌；不得解释为曝光后未点击。训练轮次、负采样和正则只用验证集确定，至少 3 个固定种子，记录最优 checkpoint 选择规则。

### 研究扩展：语义→行为共享适配器

```text
z_i = frozen_text_encoder(item_i)
p_i = g_theta(z_i)  # 1024 → 256 → 128 的共享 MLP 示例
L = -log sigmoid(u · p_pos - u · p_neg) + α × regularization
对比：相同容量线性映射 / MLP；纯内容 / 纯 CF / 简单融合。
```

这只是受 PACERec 启发的简化实验，不宣称复现论文。文本向量空间与 CF 空间不同，必须通过学习映射或候选/特征融合，不能直接相加。若添加语义保持项，应在相同空间定义余弦/邻域约束并另做消融，避免不透明的多损失组合。

无查询推荐融合固定为：s = β × rank01(ItemCF 分数) + (1−β) × rank01(训练喜欢项平均文本向量与候选的余弦)；β 在 {0,0.25,0.5,0.75,1} 中用推荐验证集选。相同分数取平均秩，缺失 CF 分数为 0，最终并列按 ID。主线验证 warm-item 与 tail；已知目录零训练交互商品作为独立扩展，采用训练期拟合的映射并在未参与拟合商品上测试。不要用“有少量交互”代替冷物品，也不要把全目录拟合的 PCA 写成严格未见泛化。

适配器无稳定提升时保留负结果。对于第一份实习，一套公平实验与可定位失败的服务，比重复已有论文的复杂结构更有价值。

## 12 / Agent 的决策流程

有限循环也能体现真实工具使用；明确何时结束、恢复和澄清。

**流程图文字版：** 接收消息 → 加载会话 → 模型选择澄清/工具/回答 → 参数与权限校验 → 工具执行 → 更新状态和证据 → 再次决策 → 输出校验 → 返回。无效参数最多修复一次；预算或超时触顶时返回有据部分结果。

| 控制项 | 默认设计值（开发阶段可测后锁定） |
| --- | --- |
| 每个用户回合 | 最多 4 次 LLM 调用（含最终生成和修复），6 次工具执行，最多 1 次参数修复；不能分别无限重试。 |
| 输入输出 | 模型上下文应用上限 8k；每次生成最多 768 tokens；短工具结果，只保留 top10 和字段证据。 |
| 超时 | 读工具上限 5 秒、模型上限 30 秒、回合总限 60 秒；各调用 timeout=min(单次上限, 剩余时间)。重试/退避共享同一 deadline。 |
| 确定性保护 | 工具白名单；Pydantic 校验；商品 ID 校验；写操作幂等；来源版本检查；约束与事实输出验证。 |

MVP 可用一次工具选择加一次回答；完整版根据工具结果再次决策。总期限用单调时钟，触顶取消后续调用与写入；提交前再次检查期限。UI 只显示检索/比较进度，不展示隐藏推理。

LangGraph 可作为后续状态持久化替代；首版显式状态机足够。不要同时维护两套编排框架。模型原生工具协议不兼容时，可使用受校验的结构化 action JSON 适配。[S6]

## 13 / 工具与接口契约

业务函数同时服务 HTTP 接口和 Agent，避免两套排序逻辑。

| 工具 / 对应接口 | 输入与行为 | 约束 |
| --- | --- | --- |
| search_catalog<br>POST /v1/search | query、constraints、limit；返回排名、原因码、证据与版本。 | limit 1—10；身份从服务会话注入，模型不可指定其他用户。 |
| recommend_items<br>POST /v1/recommend | 当前用户/喜欢项、可选类别与约束；返回冷启动标记。 | 当前明确约束优先于历史；已交互屏蔽规则一致。 |
| compare_items<br>POST /v1/compare | 2—4 个商品 ID、比较维度；返回逐字段证据。 | ID 必须属于当前目录且在会话可见；未知字段返回 null。 |
| read_preferences<br>GET /v1/preferences | 读取本会话与用户明确保存的偏好。 | 不能读取其他用户；区分显式与推断。 |
| write_preference<br>POST/DELETE /v1/preferences | set/delete、key/value、scope、来源消息 ID。 | 持久化需要明确“记住/删除”的用户语句；模型自称获授权不算。 |
| update_shortlist<br>POST /v1/shortlist | add/remove、item_id、request_id。 | 明确用户意图；同一幂等键不重复执行。 |

聊天 POST /v1/chat；反馈 POST /v1/feedback；诊断 GET /v1/traces/{id}。工具直接调用业务函数。搜索返回时服务原子更新 visible_item_ids 与 last_result_order，“前两个”只解析最近有效结果；响应带 trace_id 与目录/画像版本。

### 统一失败返回

```text
{"ok": false, "error_code": "NO_MATCH",
 "retryable": false, "message": "全目录已核验：无满足结构化条件的商品",
 "trace_id": "...", "catalog_version": "..."}
```

其他错误码：RETRIEVAL_INCOMPLETE（未完整检索）、INVALID_ARGUMENT、UNKNOWN_ITEM、VERSION_MISMATCH、TOOL_TIMEOUT、BUDGET_EXCEEDED。无解与未找到严格区分。

## 14 / 结构化结果与证据检查

示例 ID、数值与字段仅说明格式，不是已经存在的商品或实测结果。

```text
{
  "trace_id": "demo_001",
  "catalog_version": "office_v1",
  "applied_constraints": {"max_price_usd": 40},
  "items": [{
    "item_id": "DEMO_ITEM_01", "rank": 1,
    "route_ranks": {"lexical": 4, "dense": 2, "cf": 9},
    "price_usd": 29.9,
    "reason_codes": ["query_match", "similar_to_liked"],
    "evidence_ids": ["ev_title_01", "ev_price_01"],
    "missing_attributes": ["width_cm"]
  }],
  "warnings": ["historical_price_usd"]
}
```

### 答案结构优先于自由发挥

模型输出 selected_item_ids、comparisons、claims 和短解释；每条事实 claim 绑定 evidence_id 与 item_id。商品卡片的名称、价格、维度由程序从证据字段渲染，模型不重写数值。引用合法不等于事实被支持，必须进一步核对字段、值、对象与版本。

对于“适合你”这样的判断，显示推理依据，例如“与你明确喜欢的 X 在用途上相似”，并标为偏好推断；对于“质量最好”“最安静”等没有证据的断言，输出前删除或改成未知。复杂自然语言推断保留人工审查，不声称程序能完全自动验证。

### 被检索内容不是控制指令

商品描述和评论一律作为数据传入，不拥有工具执行或记忆写入权限。测试加入“忽略预算”“读取其他用户”等污染文本，验证系统仍遵守服务层约束。有效事实引用与工具输入校验是两层独立保护。

DeepSeek 和本地 Qwen 共用上述输出契约；提供方的 JSON/tool 格式支持不能代替本地业务校验。

## 15 / 会话、记忆与反馈

显式约束可覆盖旧偏好；每次状态变化都能解释来源。

| 信息类型 | 存储与有效期 | 冲突处理 |
| --- | --- | --- |
| 本次约束 | session：这次预算、类别、排除项、最近候选。会话结束或用户清空后失效。 | 最新明确表达覆盖旧值；“不要记住”禁止提升为长期偏好。 |
| 长期明确偏好 | persistent：仅记录用户明确要求保存的品牌/用途等；记录来源，可查看删除。 | 本次明确约束优先；长期偏好不能导致违反当前要求。 |
| 推断兴趣 | 历史喜欢项/训练行为聚合；作为软评分，不描述为确定个人属性。 | 一个 dislike 只排除该商品；不推断整个品牌永久不喜欢。 |
| 演示反馈 | like/dislike/save 事件，区分 real_demo 与 synthetic_test。 | 立即更新会话排序特征；不自动改变离线模型，不混入正式测试训练。 |

### 优先级

当前用户明确指令 ＞ 当前会话约束 ＞ 已保存明确偏好 ＞ 推断兴趣。两条当前硬约束矛盾时先澄清，不在后台自行选择其一。普通点击只能当演示交互事件，不能直接赋值为“喜欢”。

### 并发与幂等

每次偏好写入使用 expected_profile_version；版本冲突时重载再处理。清单写入用 request_id + action + item_id 去重。一个用户的会话不得改变另一用户的画像；测试同时打开两个会话验证隔离。

### 重复请求也要安全

模型/API 重试可能重放工具调用。只读工具可缓存，写操作必须返回已有执行回执。用户取消或预算触顶后停止后续模型/工具调用，已完成写入如实展示，不伪装成全部回滚。

单卡即可作为主路径；3060 不承担必须成功的大模型部署。

| --- | --- |
| 生成模型 | Qwen3-4B-Instruct-2507，非思考模式、成熟候选而非“最新最强”宣称；A6000 上单模型服务，应用上下文 8k。[S7] |

### 显存与容量估算的边界

4B 参数 BF16 权重约 8 GB，仅为权重下界；KV cache、激活、运行时和并发还会占用显存。A6000 可用显存、是否共享、CPU/RAM/磁盘均需第 1 天实测。不得用模型宣称的最大上下文直接作为服务配置。

先固定并发 1，记录吞吐、首字延迟、总延迟和峰值显存。模型模板/工具解析器以官方文档与实际 20 个兼容性样例为准；锁定可工作的依赖、模型 revision 与 chat template，不直接追最新版本。[S6][S8]

可选依赖尽量分环境：离线训练与推理服务各锁依赖。仅有 Python+CPU 时应能跑 100 件自制样例的搜索、参数校验和回放测试。

## 17 / DeepSeek 可选模式与费用控制

采用同一工具协议；API 的价值是提高调试效率，不是让项目依赖付费。

设计提供 provider=local / deepseek 两个实现。官方文档当前列出 deepseek-flash（对应 DeepSeek-V4.1-Flash-1017），支持工具调用；初版显式关闭思考。模型别名可能更新，日志保存请求名、返回模型标识、日期和 token 用量。[S9][S10]

| 截至 2026-10-20 / 元每百万 tokens | 高峰 | 空闲 |
| --- | --- | --- |
| 输入：缓存未命中 | 2 | 1 |
| 输入：缓存命中 | 0.04 | 0.02 |
| 输出 | 8 | 4 |

保守估算使用高峰且无缓存：费用 = 输入 tokens / 1,000,000 × 2 + 输出 tokens / 1,000,000 × 8。所有轮次重复上下文、失败重试、修复调用均计入；以实际返回 usage 和账单复核。

### 一组可理解的预算示例

若 200 个完整任务每个累计输入 8,000、输出 1,000 tokens，总输入 160 万、输出 20 万，则高峰约 4.8 元，空闲约 2.4 元。它只是假设用量的算术示例，真实对话更长或重试更多时费用会增加。价格上线前复核。[S9]

### 预算机制

默认 api_enabled=false。20 元可作为一次实验的配置示例，金额由你启用时决定；此设计没有充值或付费调用。每次请求先按最大 token 和保守单价预留额度，再结算实际用量；并发先设 1，保留安全余量，触顶停止，不自动切付费备用模型。

工具执行使用本地目录服务，无需网页 Search/Fetch API。密钥只放环境变量；公开数据最小字段可以传入 API，未投稿论文、原始用户身份或无关日志不放进 prompt。主评测可全部本地运行，API 对照只需固定小子集。

本地推理也有时间与硬件占用成本；API 账单为零不等于计算免费。两种模式各报告实际延迟与质量，不将换模型的收益归因于排序改进。

## 18 / 工程可观测性与失败恢复

项目应能说明“哪里错了、如何退回、是否影响结果”。

| 异常 | 系统行为 | 日志与验证 |
| --- | --- | --- |
| 向量服务不可用 | 保留词面召回；响应标注降级；结果仍过约束与证据校验。 | 记录失败阶段、route_disabled 与候选变化。 |
| 无匹配/价格未知 | SQL 全目录确证后才报无解；仅候选为空报“本次未找到”；用户可主动放宽。 | 不把未知价格判为低价；固定无解用例。 |
| LLM 超时/格式错误 | 至多一次修复，计入总调用数；否则返回已有商品卡片和未完成说明。 | 所有超时计入成功率分母与端到端耗时。 |
| 429/服务错误 | 有限退避重试且受总期限和费用预留控制；不连环切换提供方。 | 区分网络、额度与业务失败。 |
| 状态/版本冲突 | 拒绝跨版本 ID 或过期写入，重载后再执行。 | 双会话隔离、重复写入、索引错配测试。 |
| 模型编造事实 | 程序核对对象/数值/证据；删去无法支持的 claim 或使用模板回答。 | 保留未支持事实数和人工复核结果。 |

### 每次请求最少记录什么

trace_id、匿名用户/会话、数据/模型/prompt 版本；每路召回数量、过滤原因、最终 IDs；工具次数、状态变化、首字/总延迟、阶段耗时；输入/输出 tokens、费用估算、峰值显存与异常类别。密钥不入日志，正文按调试需要最小保留。

### 配置与缓存

缓存键包含 catalog/index/model/prompt/profile 版本、规范化查询和约束，避免给新偏好返回旧结果。索引生成完成后通过 manifest 原子切换；加载时校验 ID 和维度。先有可追踪 JSONL，后续再考虑监控平台。

## 19 / 推荐评测：能证明什么

衡量冻结历史对未来正向评论商品的排序能力，不能外推为线上点击收益。

| 项目 | 定义 |
| --- | --- |
| 统一协议 | 第 08 节的同一目录、用户、时间边界和屏蔽规则；测试用户最多 5,000，抽样仅基于身份哈希并记录实际覆盖。 |
| 必要基线 | 训练热门；ItemCF；内容历史聚合；CF+内容融合。BPR/适配器属于可选附加，不能删掉简单强基线。 |
| 主指标 | Recall@20 与 NDCG@10。每用户单一目标时 Recall 等于命中率；NDCG 命中时为 1/log2(rank+1)，否则 0。 |
| 分阶段诊断 | 候选 Recall@100（统一诊断预算）与最终 NDCG；业务 top600 结果另报，不混用不同候选数。 |
| 分桶与覆盖 | 训练 tail/head、用户历史长度、目录覆盖率。失去主评测资格的群体单独列数量和占比。 |
| 统计与复现 | 固定种子、超参表和 checkpoint；训练模型 3 个种子报均值/标准差；按用户 bootstrap 1,000 次估计配对差值区间。 |

### 公平的比较方式

所有模型使用相同训练数据、相同目标与全目录候选；不让一方看到测试用户后续历史。调参预算约束在相近范围，最佳配置只由验证选择。若训练多种子，报告每种子的测试值，不能只选最好测试结果。

### 必须留下负结果

若融合弱于 ItemCF，优先检查冷用户比例、目录过稀、语义与行为不一致、候选召回漏失；若个性化只对长历史用户有效，明确这个边界。追求可解释而稳定的结果，不预写“提升 10%”作为必须实现的结论。

全目录主评测避免采样评价改变模型排序的问题。[S11] 如额外报告采样 AUC，单列采样方案并说明不是点击概率校准。

## 20 / 搜索评测：独立查询与相关性

公开评论数据没有原生搜索日志，必须另建可核验的查询集。

必做 60 条请求：20 条开发、40 条锁定测试；测试按 20 中文、20 英文组织，并覆盖用途、类别、精确词、否定、预算及无解。中英文不能是同一题的直译跨开发/测试泄漏；按意图模板/商品族划分，冻结查询、约束与可接受范围。

| 环节 | 执行方法 |
| --- | --- |
| 候选池标注 | BM25、Dense、RRF 各 top10 合并去重，最多 30 项/请求；统一盲标 0/1/2 级相关性，记录硬约束是否满足。约最多 1,800 对。 |
| 标签规则 | 2=满足主要用途且可接受；1=部分相关但需取舍；0=无关或违反硬约束。先写用户需求，再看随机化候选；标注来源隐藏。 |
| 评价范围 | nDCG gain=2^label−1；IDCG>0 查询才计入均值。MRR 以标签 2 为相关，仅在存在标签 2 的查询统计；分别报分母。 |
| 正式候选变化 | 固定系统后补齐其 top10 标签并封存，报告池覆盖；未知不当负例。无解题单独评准确率，真值由全目录结构化检查确定；无正例池不直接当无解。 |
| 比较配置 | BM25；Dense；RRF；RRF + 同一轻量 reranker。相关模型/字段/候选深度在开发集固定。 |
| 约束与语言 | 另报硬约束违规、无解判断、中文与英文效果。跨语言提升不可归功于 CF，改写器与编码器作用分开分析。 |

池内 IDCG 仅覆盖已标注商品，不等于全目录理想排序。单人标注可以完成，但要公开其偏差。若有同学协助，复核 10 个测试查询及分歧；不依赖付费 LLM 裁判。允许模型草拟开发问题，主测试需求由人工检查，不能从目标标题复制答案后制造高分。

可选 ESCI-US：使用官方查询/标签与已标注候选做独立重排验证，不与 Reviews 用户历史强行拼接，也不宣称全目录搜索或个性化效果。[S12]

## 21 / Agent 评测：终态、事实和稳定性

60 题：20 开发 + 40 锁定测试；每个测试任务重复 3 次，每配置共 120 次回放。

| 测试类别 | 40 题分配 | 必须检查 |
| --- | --- | --- |
| 单轮明确约束 | 10 | 合法商品、预算/属性满足、证据支持。 |
| 需要澄清 | 5 | 关键条件缺失时正确询问；脚本用户提供固定答复。 |
| 多轮修改/撤销 | 5 | 新条件覆盖旧条件；清单和偏好最终状态正确。 |
| 历史与当前冲突 | 5 | 当前意图和硬约束优先；不被偏好带偏。 |
| 比较与替代 | 5 | 比较的对象和字段正确；未知值明确标示。 |
| 无解/信息缺失 | 5 | 不编造产品或属性；不擅自放宽条件。 |
| 超时/异常/污染 | 5 | 预算内终止；有限恢复；不执行商品文本指令。 |

每题固定画像、目录、用户脚本、澄清上限、可接受集合、证据和终态；无解真值独立检查全目录。每次从同一数据库快照恢复、换 request_id、关闭答案缓存；温度 0.2，种子 11/22/33 跨配置配对；提供方不支持 seed 时记录限制。

### 核心判分

Task Success = 商品合法 + 全部硬约束满足 + 必要澄清完成 + 核心事实有证据 + 预期终态正确 + 预算内结束；任何必需条件失败则该次失败。商品答案可有多个，不能只认一个固定 ID。

分别报告 120 次总体成功率，以及 40 题中“三次都成功”的占比；后者不是三次任一次成功的 pass@3。另报违规次数/有约束回放数、无依据事实条数/事实条数、恢复成功数/注入异常次数；按任务做置信区间与分桶。

已有历史任务另人工预标 0/1/2 偏好等级，报告展示 Top3 的偏好 nDCG，避免合法通用答案掩盖个性化差异；不以同一个 CF 分数当真值。人工复核 20 份解释，按任务聚类统计。[S13] 小样本不是生产保证。

## 22 / 实验矩阵与验收门槛

先锁定协议和目标；真实结果可以不达标，但必须完整报告。

| 组别 | 最小对照 | 回答的问题 |
| --- | --- | --- |
| 后端算法 | 热门 / CF / 内容 / 融合；BM25 / Dense / RRF / 重排。 | 行为与语义是否互补；召回还是重排造成瓶颈。 |
| Agent 系统 | 同工具/状态/写入能力的固定顺序流程；同模型 Agent+通用排序；Agent+个性化。 | 区分调度与个性化；若基线功能不足，只比共同任务并报告覆盖。 |
| 故障与消融 | 移除状态或证据约束的受控离线变体；正常/超时/污染输入。 | 可靠性来自哪些机制；消融只用于隔离测试。 |
| 模型提供方 | 本地 Qwen 为全套主实验；可选同一冻结子集 DeepSeek 对照。 | 保持工具、提示与上限一致；输出质量、延迟、成本同时比较。 |

### 完成门槛与性能目标分开

完成门槛：数据/版本校验通过；测试集锁定；工具合法性、会话隔离、写入幂等测试通过；全部结果含失败；能从新环境复现。算法指标不要求人为指定涨幅。

作品集目标：Agent 成功率 ≥80%；有约束任务违规率 ≤5%；关键事实证据可追溯 ≥95%。这些门槛在开发结束前锁定，测试不达标应说明原因并修复后启用新版评测，不能事后降低标准。

### 延迟实验

后端并发 1 和 5 各 200 个固定请求，冷/热缓存分开；报 p50、p95、吞吐、失败率，包含查询编码。无生成式改写的检索排序目标 p95 ≤1 秒，启用改写另报全耗时；Agent 单并发 p95 ≤20 秒，含所有工具与模型调用。超时按截止时间计入，不能只统计成功样本。

三个 Agent 主配置共 360 次正式回放；扩展和修复另计。先用 10 个开发任务估算本地总耗时再排批作业。外部模型对照不与后端结构变化同时进行。

## 26 / 风险、止损与广告扩展

重点防止作品过大、指标失真和模型替代工程。

| 风险 | 提前检查 | 止损方式 |
| --- | --- | --- |
| 行为数据过稀 | 训练活跃用户与目标覆盖率；目录层级过窄。 | 扩大类目或缩小研究问题；保留内容与热门基线，不伪造点击。 |
| 历史/元信息泄漏 | 特征来源、全量聚合、标题快照、测试参与选择。 | 剔除未来汇总；注明静态文本假设；保存独立协议。 |
| Agent 看似能聊但不可靠 | 参数错误、错误 ID、无证据断言、跨会话偏好。 | 程序约束与终态测试优先；工具减少至必要集合。 |
| 单卡资源争抢 | 训练与服务同时运行、过大上下文、缓存失效。 | 分阶段运行，限制上下文/并发；API 仅显式启用。 |
| 六周范围膨胀 | 同时加 LoRA、RL、序列模型、多 Agent 与广告。 | 先完成基线与演示；扩展三选一，不能挤占正式评测。 |

### 广告选做：一个清晰标识的赞助位模拟器

在合格候选中，给 synthetic_campaign 配置出价、预算和投放节奏；用明示的合成质量分与出价决定赞助位。所有广告仍通过查询相关性与硬约束检查，UI 标“模拟赞助”。记录预算超支率、标识完整率、约束违规率及有机结果 NDCG 变化。

模拟质量分不命名为真实 pCTR；评论数据不能验证真实 CTR/CVR、ROI 或竞价收益。没有曝光与倾向日志，也不宣称完成可信因果离线策略评估。该扩展用于说明广告系统约束意识，不作为两周或六周必须完成项。

### 最值得优先投入的工作

在你的研究基础上，首要价值是能证明：一个后端排序改动如何影响 Agent 的最终任务；一次失败如何通过日志定位；一张指标表如何排除数据泄漏和不公平对照。完成这些，再做更复杂模型。
