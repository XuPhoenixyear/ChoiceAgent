# 商品中文展示与术语审查

本文件记录 2026-10-21 对冻结商品目录的中文适配审查、受控词表和展示层约束。`reports/localization_inventory.json` 含真实词频、字典建议和 9 个中文查询的检索结果。最终中文缓存已覆盖全部 3,000 件商品；覆盖与来源保留检查不代表语义翻译准确率。

## 数据范围

当前目录是 Amazon Reviews 2023 的 `Office_Products` 元信息前 3,000 条有效、不重复记录；它是前缀样本，不是随机样本，也不代表整个办公用品市场。原始来源、哈希及完整重建方式见 [DATA.md](DATA.md)。商品信息、价格与是否停产等字段都是历史快照，不能解释成实时库存或当前售价。

目录的 `category` 来自元信息 `main_category`，共 23 个不同值，其中 `Office Products` 为 2,140 条，其余 860 条分布于家居、电子、工业用品等分类。因此，只翻译 `Office Products` 无法覆盖这个数据文件。所有 23 个主类的中英文对应已收入清单；各分类路径共有 392 个不同组成词，属性键共 332 个。建议词典目前包含 65 个常见路径词与 45 个常见属性键，其他值需明确回退到原文。

| 原始主类 | 商品数 | 建议显示 |
| --- | ---: | --- |
| Office Products | 2,140 | 办公用品 |
| Amazon Home | 237 | 家居用品 |
| All Electronics | 207 | 电子产品 |
| Industrial & Scientific | 85 | 工业与科研用品 |
| Tools & Home Improvement | 77 | 工具与家装 |
| Computers | 70 | 电脑及配件 |

以上仅列出数量最多的六类，完整主类表在清单的 `main_categories`。分类路径和属性的计数按每件商品是否含该字段计算；属性高频值是源字符串的精确计数，不把近义词或大小写变体合并成新的事实。

## 展示层与源事实

中文适配采用新增 `display` 层的方式。原始 `title`、`category`、`features`、`attributes` 与 `evidence` 保留原文；用户可展开原文核对。翻译是便于阅读的派生表达，不能新增商品性能、补齐缺失参数，也不能成为新的事实证据。

字段字典的键保留源字段标识。界面可以把 `Material` 标成“材质”、把 `Item Weight` 标成“商品重量”，但请求和比较仍使用原来的字段标识。分类下拉框使用中文标签和英文 canonical value，不能把“办公用品”等标签直接送入只处理英文源类目的过滤条件。品牌、型号、制造商零件编号、SKU、URL 原样显示。

建议的本地化函数合同如下，具体状态字段以当前 API 实现为准：

```python
source_hash(product: Product | Mapping[str, Any]) -> str
category_label(raw: str) -> str
field_label(raw: str) -> str
localize_value(field: str, value: Any) -> Any
CatalogLocalizer(path: Path | None = None).display(product) -> dict[str, Any]
```

缓存采用逐行 JSON，至少包含 `item_id`、`source_hash`、中文 `title`、`category`、至多前三条 `features`、`attributes`、`translation_kind`、`model` 和 `translation_version="zh-CN-v1"`。缓存中的属性保留原始英文键，值可用中文；显示标签通过字段字典提供。

源哈希只覆盖 `title`、`category`、`category_path`、`brand`、前三条 `features` 和 `attributes`，使用 UTF-8、JSON 排序键、`ensure_ascii=False` 和紧凑分隔符 `(',', ':')` 后求哈希，不包括 `item_id`。同一个 ID 的这些源字段变化时，旧缓存不得继续套用；仅 ID 不同但内容相同不应改变内容哈希。前三条之外的卖点未参与翻译哈希，不应声称已经全部翻译。

缺失缓存、源哈希不符或解析失败时应回退为受控词典与原文，保留“未知”或空值的原始含义。客户端需能区分机器翻译、字典翻译和原文回退，不把回退冒充翻译完成。单个缓存记录损坏不应让整个目录无法加载。

## 关键属性与数值规则

高频字段包括品牌 2,728 条、重量 2,629 条、颜色 1,896 条、商品尺寸 1,666 条、材质 1,350 条、规格 1,025 条。完整数量和每个键的前 15 个源值在清单的 `attribute_keys`。

- 按属性键翻译精确已知值，例如 `Material=Paper` 显示“纸”，`Color=Black` 显示“黑色”；未知字符串保留原文。
- `Yes`、`No` 只有在明确的布尔字段中才显示“是”“否”，不对所有字段执行全局字符串替换。
- 数字、币种与单位保留源表示，不默默把英寸换成厘米，也不把历史 USD 价格换算成当前人民币。需要换算时，应另列派生字段和换算依据。
- `Size=Letter` 表示美式 Letter 规格，不能译为“信件”；`Closure` 的笔具收合与文件夹闭合含义应结合字段语境。
- `Date First Available` 是“首次上架日期”，不能翻译成当前到货时间；`Page Yield` 可标注“标称打印页数”，不能当作实测性能。
- `Manufacturer=0` 等源异常必须保留或明确提示异常，不能猜测厂商。缺失材质、规格或品牌不得由模型补全。
- 原始宣传语中的“高品质”等只能作为原始描述的翻译，不能升级为系统背书。

## 中文检索覆盖审查

审查使用当前真实目录、SQLite 词面检索、无预算约束、关闭个性化，每个查询取前五条。它不加载模型、不调用外部 API、不使用 GPU，也不代表完整混合检索效果。全部查询都被现有受控词表改写并返回结果；以下是标题和分类路径的人工快速核查，不能当作正式相关性标注或精确率评测。

| 中文查询 | 当前词面改写 | 观察到的主要问题 |
| --- | --- | --- |
| 桌面收纳 | desk organizer | 返回桌面收纳商品；存在文具与化妆品多用途交集。 |
| 钢笔 | fountain pen | 第 2 条是钢笔墨囊，主商品与配件混淆。 |
| 打印纸 | printer paper | 第 1、3 条为迷你打印机，第 4 条为打印机纸盒。 |
| 办公椅 | office chair | 第 1、3 条为椅轮，第 4 条为扶手垫。 |
| 订书机 | stapler | 第 4 条是装修用打钉枪，需要区分用途。 |
| 鼠标垫 | mouse pad | 前五条标题未见明显类型冲突。 |
| 笔记本 | notebook | 当前解释为纸质笔记本；与电脑含义存在歧义。 |
| 文件夹 | folder | 第 3 条为文件夹标签。 |
| 白板 | whiteboard | 第 4 条为磁铁；白板膜与白板也有形态差异。 |

逐条商品 ID、源标题、分类路径、名次及问题标注见 `query_audit`。中文翻译能改善可读性，但不会自动修正这些主商品与配件的排名问题。本轮展示适配不调整检索排序。后续独立检索工作可考虑以叶类目优先确认商品类型，再用标题回退，并为墨囊、椅轮、扶手垫、纸盒、标签和磁铁等配件建立类型排除规则。对“笔记本”“订书机”等歧义先澄清用途更稳妥。

## 验收边界

自动化测试验证源哈希与缓存失效、未知字段回退、数值和单位保留、缺失值语义、原始事实不可变，以及翻译不会新增证据。浏览器验收检查搜索卡片、详情、比较表、收藏和 Agent 回复是否一致使用中文展示，且仍能查看原文和证据。初轮术语清点与后续机器翻译分别记录；完整构建与实际验收结果见下节。
