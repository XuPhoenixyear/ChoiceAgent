# 真实界面验收记录

最终有效素材位于 `reports/demo/final/`。2026-10-21 使用真实 Chromium、Streamlit、核心 API 及本地 Qwen3-1.7B 服务录制；没有 mock、请求拦截或替换画面内容。最终 12 项检查全部通过，浏览器 JavaScript 异常与 console error 均为 0。原始视频约 69.92 秒，MP4 为原速播放，5 张截图均来自该次实际操作。

## 验收中发现并修复

1. 先“喜欢”后进入聊天时，聊天成功会清除上方提示；提示数量改变导致 Streamlit 重新创建标签组，跳回“搜索商品”。将提示区放进始终存在的容器，保持标签位置稳定。最终录制额外断言第一轮与第二轮回复后“聊聊需求”仍然激活，均通过。
2. 首轮自动化使用 Playwright 的 `check()` 点击 Streamlit 开关的底层 input，被开关自身的 label 遮挡。这是自动化定位问题；录制脚本改为聚焦真实开关并按空格，保留正常控件事件，没有强制点击、修改 DOM 或伪造状态。预算筛选最终通过。
3. 默认界面曾露出 Streamlit 的 Deploy 工具栏及英文品牌占位文字。隐藏框架工具栏，并把品牌选择占位文字改为中文。

- 中文搜索“适合小桌面的收纳盒”，启用 35 美元历史预算，返回的可见价格均不超过上限。
- 喜欢状态在页面重绘后保留；选择两件已展示商品后成功比较历史价格、品牌与类别。
- 第一轮聊天预算 35 美元：11.95、21.67、13.99、15.92、18.45。
- 第二轮修改为 20 美元：11.95、13.99、15.92、18.45、19.99。
- 以上价格均为资料中的历史美元价格，不能用于推断实时售价、库存或中文搜索的整体检索质量。
- `ruff check` 和 `mypy` 对两个实现模块通过；17 项界面纯函数测试通过。

`reports/demo/ui_acceptance.json` 和 `reports/demo/verified/ui_acceptance.json` 保留前两次失败验收，便于核对修复依据；对外交付应使用 `reports/demo/final/`。录制脚本的新一版额外调整聊天截图的滚动位置，便于后续录制显示完整用户预算消息；现有最终素材未进行图像修改。
